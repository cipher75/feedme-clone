# URL → Markdown → LLM

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 뽑아 보여주고, 복사·다운로드하거나 프롬프트와 함께 ChatGPT·Claude로 바로 넘기는 서비스입니다.

## 승인된 화면

- [prototype.html](prototype.html): 승인된 화면 프로토타입입니다. 화면 구성, 요소 배치와 순서, 상태별 모습(기본·변환 중·결과·긴 본문·가져오기 오류), 라이트·다크 표현을 정합니다. 구현에서 이 구성을 따르고, 구체적인 색·간격 값은 프로젝트 토큰과 shadcn 구성을 씁니다.
- 프로토타입이 보여주는 동작 중 spec에 명시한 것만 계약입니다. 프로토타입의 더미 글, 가짜 지연 시간, 안내 문구의 정확한 표현은 참고용입니다.
- 프로토타입에서 확정된 세부 동작:
  - 프롬프트 프리셋은 다시 누르면 선택이 해제되고, 하나만 선택됩니다. "직접 입력"도 같은 선택 그룹에 속합니다.
  - 프롬프트 선택 영역은 결과가 나온 뒤 내보내기 버튼들과 같은 묶음에 있고, 그 아래에 본문이 렌더링됩니다.
  - 가져오기 오류에는 "다시 시도" 버튼이 있습니다. 주소 형식 오류는 입력란 아래에 표시합니다.
  - 헤더에는 제목, 저자, 사이트 이름, 글자 수가 나옵니다.
  - 다크모드 토글은 화면 오른쪽 위에 있습니다.

## 사용자에게 보이는 결과

1. **입력**: URL 입력란에 주소를 붙여넣고 변환을 실행합니다. 지우기 버튼을 누르면 입력, 결과, 오류, 선택한 프롬프트가 모두 초기 상태로 돌아갑니다.
2. **변환**: 페이지 본문만 Markdown으로 변환됩니다. 변환에는 defuddle 라이브러리를 사용합니다(필수, [문서](https://defuddle.md/docs)). 호스팅 API(`defuddle.md/<url>`)는 쓰지 않고 라이브러리를 서비스 안에서 실행합니다.
3. **결과 확인**: 결과 위쪽에 페이지 제목과 저자가 나오고, 그 아래에 렌더링된 Markdown이 나옵니다. 저자를 알 수 없으면 저자 줄은 생략합니다.
4. **내보내기**
   - 복사하기: Markdown 본문을 클립보드에 복사하고, 복사됐다는 피드백을 보여줍니다.
   - .md 파일 다운로드: 파일명은 페이지 제목에서 만듭니다. 본문에 이미지가 없으면 Markdown 본문을 `.md` 파일로 저장합니다. 이미지가 있으면 서버가 이미지를 받아 `images/` 폴더에 담고, 본문의 이미지 링크를 그 상대 경로로 바꾼 `.md`와 함께 `.zip` 파일 하나로 저장합니다. 받지 못한 이미지는 원래 주소를 그대로 둡니다.
   - ChatGPT로 열기 / Claude로 열기: 새 탭에서 해당 서비스를 열고, 선택한 프롬프트(없을 수 있음)를 앞에 붙인 본문을 입력창에 채워 둡니다.
5. **프롬프트**
   - 프리셋: 요약해줘 / 한국어로 번역해줘 / 쉽게 설명해줘, 그리고 "직접 입력".
   - "직접 입력"을 고르면 텍스트 입력란이 나타납니다. 입력한 내용은 저장하지 않고 이번 사용에만 적용합니다(새로고침하면 사라집니다).
   - 프롬프트는 선택 사항입니다. 선택하지 않으면 본문만 넘깁니다.
   - 넘기는 형태는 `프롬프트`, 빈 줄, `Markdown 본문` 순서입니다. 프롬프트는 "복사하기"와 "다운로드"에는 붙지 않습니다.
6. **다크모드 토글**: 화면에서 라이트와 다크를 전환할 수 있습니다.

## 수용 기준

- 공개된 일반 기사 URL(예: `https://stephango.com/saw`)을 넣으면 제목, 저자, 본문 Markdown이 표시된다.
- 지우기 버튼 한 번으로 입력·결과·오류·프롬프트 선택이 초기화된다.
- 변환 중에는 진행 중임이 보이고 중복 실행이 되지 않는다.
- 잘못된 URL, 접근할 수 없는 페이지, 본문 추출 실패는 각각 알아볼 수 있는 오류 메시지로 보이고, 다시 시도할 수 있다.
- 복사하기를 누르면 본문이 클립보드에 들어가고 피드백이 보인다.
- 이미지가 없는 글을 다운로드하면 `.md` 파일에 본문 Markdown이 담긴다.
- 이미지가 있는 글을 다운로드하면 `.zip`에 `.md`와 `images/` 파일이 담기고, `.md`의 이미지 링크가 `images/...` 상대 경로를 가리킨다. 받지 못한 이미지는 원래 주소로 남는다.
- 본문의 이미지는 결과 화면에 표시된다. 다른 사이트에서의 요청을 막는 서버(예: 네이버)의 이미지도 보인다.
- 복사하기와 ChatGPT·Claude로 열기는 이미지를 원래 주소 그대로 둔다(본문에 이미지 데이터를 넣지 않는다).
- ChatGPT·Claude로 열기는 선택한 프롬프트가 본문 앞에 붙은 채로 입력창에 채워진다. 프롬프트를 고르지 않으면 본문만 채워진다.
- 프롬프트+본문이 URL로 넘기기에 너무 길면, 전체 텍스트를 클립보드에 복사한 뒤 서비스를 새 탭으로 열고 "붙여넣기 하세요"라고 안내한다. 본문은 잘리지 않는다.
- "직접 입력"이 아닐 때는 텍스트 입력란이 보이지 않고, 직접 입력한 문구는 새로고침 후 남지 않는다.
- 다크모드 토글로 화면 전체의 테마가 바뀐다.
- 좁은 화면에서도 모든 동작(입력, 결과, 내보내기, 프롬프트)을 쓸 수 있다.

## 확정된 제약과 이유

- **defuddle 라이브러리 필수**: 사용자가 지정했습니다. 호스팅 API는 요청 수 제한과 유료 과금이 있어 서비스의 기본 경로로 삼지 않습니다.
- **변환은 서버 쪽에서 실행**: 브라우저에서 임의의 외부 페이지를 직접 가져오면 CORS로 막히므로, 서비스가 페이지를 대신 가져와 변환합니다. 라이브러리 동작은 임시 환경에서 확인했습니다(defuddle 0.19.5 + linkedom, `defuddle/node`의 `markdown: true`로 제목·저자·Markdown 본문 추출 확인).
- **긴 본문은 클립보드 우회**: 사용자가 선택했습니다. 본문 손실을 피하는 대신, 한 번 붙여넣기 하는 수고를 받아들입니다.
- **UI 구성**은 [ui-composition](../../decisions/ui-composition.md) 계약을 따릅니다. 일반 UI는 shadcn으로 구성하고, 상태(로딩·빈 상태·오류·성공)를 정상 화면과 함께 설계합니다.
- 렌더링된 Markdown에는 원본 페이지의 스크립트가 실행되지 않아야 합니다.
- **이미지는 복사·열기 경로에 넣지 않고 다운로드에만 담습니다**: 이미지 데이터를 본문에 넣으면 URL 한도와 LLM 토큰 사용량이 크게 늘기 때문입니다. 사용자가 다운로드 파일에도 이미지를 담기를 요청해 확정했습니다.
- **네이버 블로그**는 껍데기 페이지 안의 본문 프레임을 따라가 글 본문만 가져옵니다.

## 가정 (바꿀 수 있음)

- 지원하는 주소는 `http://`, `https://`뿐입니다.
- 한 번에 URL 하나만 처리합니다.
- ChatGPT·Claude로 열기는 각 서비스가 지원하는 쿼리 파라미터(`?q=`)로 입력창을 채웁니다. 서비스 쪽 동작이 바뀌면 이 부분이 깨질 수 있습니다.
- URL로 넘길 수 있는 길이의 기준은 구현 때 보수적으로 정합니다.
- 다크모드 기본값은 OS 설정을 따르고, 사용자가 고른 값은 이 브라우저에 기억합니다.
- 결과 화면의 Markdown은 렌더링된 형태만 보여주고, 원문 Markdown 보기 전환은 두지 않습니다.
- 로그인이 필요한 페이지, JS로만 그려지는 페이지는 지원하지 않으며 추출 실패 오류로 처리합니다.

## 범위 밖

- 계정, 변환 이력 저장, 프롬프트 저장.
- 여러 URL 일괄 처리, 파일·PDF 입력.
- ChatGPT·Claude 외 다른 LLM 연동, LLM 직접 호출(API 연동).
- 속도 제한, 악성 주소 방어 같은 하드닝.

## 남은 위험

- 이미지 다운로드는 서버가 본문에 적힌 이미지 주소를 그대로 가져옵니다(최대 50개, 개당 15초 제한). 주소 검증이나 크기 제한 같은 방어는 하지 않았습니다.
- 서버가 TLS 인증서를 신뢰하지 못하면(사내 프록시 환경) 페이지 가져오기가 실패합니다. 이때는 서버 실행 환경에 `NODE_EXTRA_CA_CERTS`로 인증서를 지정해야 합니다.

- ChatGPT·Claude의 `?q=` 동작과 길이 한도는 외부 서비스 사정으로 바뀔 수 있습니다. 한도를 넘으면 클립보드 경로로 대체되므로 본문 전달 자체는 유지됩니다.
- defuddle이 본문을 잘못 고르는 사이트가 있을 수 있습니다. 이때는 추출 결과가 빈약하거나 오류로 보입니다.
